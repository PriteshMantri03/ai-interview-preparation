# Deploying to Render and Vercel

## Render API

The repository includes a Render Blueprint in `render.yaml`. In Render, create a new Blueprint from this repository and set these service environment variables:

- `MONGO_URI`: your MongoDB connection string. In Atlas, allow connections from Render (or temporarily allow `0.0.0.0/0` while diagnosing connectivity).
- `GROQ_API_KEY`: a valid Groq API key; report and resume generation both call Groq.
- `FRONTEND_URL`: the exact Vercel production origin, such as `https://your-project.vercel.app`. For previews, add the preview origins as a comma separated list.
- `JWT_SECRET`: generated by the Blueprint, or set a long random value yourself.

Render uses `Backend` as the service root, `npm install` to build and `npm start` to run. Check that `https://<your-render-service>.onrender.com/health` returns `{"status":"ok"}` after deployment.

## Vercel frontend

Import the same repository into Vercel and set **Root Directory** to `Frontend`. Keep the framework preset as Vite and use `npm run build` / `dist` if Vercel does not detect them automatically. Set this build environment variable to the full Render API origin, with no trailing slash:

```text
VITE_API_URL=https://<your-render-service>.onrender.com
```

Redeploy after changing Vercel environment variables; Vite embeds them at build time. Add the resulting Vercel origin to Render's `FRONTEND_URL` and redeploy the API. Both frontend API clients use this variable and send cookies with credentials.

For local development, copy `Backend/.env.example` to `Backend/.env` and use `http://localhost:5173` for `FRONTEND_URL`. Keep real credentials in Render/Vercel environment settings and never commit them.
